# ADR 0002 — 로컬 글 작성기(스튜디오)의 배치와 계약

- 상태: **Accepted (착수는 블로그 개발 완료 후)**
- 날짜: 2026-09-24
- 관련: `docs/studio-plan.md` · `docs/PLAN.md` · `docs/authoring.md`

## 결정

| ID | 결정 | 근거 |
|---|---|---|
| G1 | **로컬 전용 웹앱.** 모바일·원격 미고려 | 개인 작업용 도구. 호스팅·인증 서버·모바일 레이아웃을 만들 이유가 없음. 로컬이면 미리보기를 `astro dev`로 띄워 **배포본과 100% 동일**하게 볼 수 있음 |
| G6 | **별도 private 저장소**에서 개발 | 블로그 저장소는 공개 사이트다. 도구는 관심사·의존성·배포 파이프라인이 완전히 다르고, 블로그 빌드에 섞이면 안 된다. 블로그 개발(M3~M7)이 끝난 뒤 착수 |
| G5 | **fine-grained PAT**, OS 키체인 보관 | 이미 검증된 방식. Device Flow·OAuth 프록시·GitHub App은 서버가 필요하거나 복잡도가 큼. 로컬 전용이므로 토큰을 브라우저에 둘 필요도 없음 |
| G4 | VS Code 확장 **불필요** | 그래프 캔버스·자료 편집·미리보기는 결국 웹뷰다. 그렇다면 UI는 어차피 웹앱이고, 확장은 배포·확장 호스트 API·메시지 브리지라는 복잡도만 더한다 |
| G3 | 그래프 편집기 **보류** | 사이트의 M4(목차 그래프)를 먼저 써 보고 편집이 실제로 필요한지 판단. 글이 적으면 GUI 편집의 효용이 낮다 |
| G7 | 스튜디오 자체는 **데스크톱 전용**, 단 **뷰포트 프리뷰 포함** | 도구 UI에 반응형은 불필요하지만, 결과물이 모바일에서 어떻게 보이는지는 확인해야 함. iframe 폭 전환만으로 충분 |

## 핵심 설계 결정 — 코드 공유 대신 "계약"

스키마·검증을 두 저장소가 공유하는 방법으로 다음을 검토했다.

| 방법 | 판정 |
|---|---|
| npm 패키지로 publish 후 양쪽에서 소비 | 기각 — 스키마가 자주 바뀌는 동안 배포 사이클이 생김. zod 인스턴스 이중화 위험 |
| git 의존성으로 하위 폴더 참조 | 기각 — **npm은 git 저장소의 하위 폴더를 의존성으로 받지 못한다**(`path:`는 pnpm 전용) |
| git submodule / 코드 복사 | 기각 — 동기화 부담, 드리프트 |
| **블로그 저장소의 검증 CLI를 계약으로 호출** | **채택** |

채택 근거:

1. 스튜디오는 어차피 **로컬 클론 위에서** 동작한다 → 블로그 저장소의 파일이 항상 디스크에 있다.
2. "그 저장소의 규칙으로 검증한다"는 것은 **내용 편집기로서 올바른 의미론**이다. 스키마가 바뀌어도 스튜디오가 자동으로 따라간다.
3. 인터페이스가 **JSON + 종료 코드**뿐이라 언어·프레임워크에 종속되지 않는다.

계약 형식은 `docs/studio-plan.md` 3장에 고정했고, `contractVersion`으로 호환성을 관리한다. 현재 구현: `npm run validate:json`.

## 이 결정의 대가

| 대가 | 완화 |
|---|---|
| 스튜디오가 블로그 저장소의 **경로 규약에 의존**한다 | 규약을 문서로 고정(`studio-plan.md` 3장) + 검증기가 규약 위반을 잡아줌 |
| 계약 형식 변경 시 양쪽 수정 필요 | `contractVersion` 증가 + 스튜디오가 불일치 시 경고 |
| 로컬 클론이 없으면 동작하지 않음 | 로컬 전용이므로 전제로 수용 |

## 검토했으나 채택하지 않은 대안

- **Electron/Tauri 데스크톱 앱**: 편집기·파일트리·diff를 처음부터 만들어야 함
- **기존 Git CMS(Decap/Sveltia)**: 그래프·자료 편집을 위젯 한계 안에서 해야 하고 OAuth 프록시가 필요
- **원격 어드민(모바일 지원)**: 서버·인증·호스팅 비용 대비 효용이 낮음(G1)
- **GitHub 웹 편집만 사용**: 그래프·검증·자료 편집 불가

# ADR 0001 — 블로그/포트폴리오 초기 의사결정

- 상태: **Accepted (전 항목 확정)**
- 날짜: 2026-09-21
- 관련 문서: `docs/PLAN.md` v0.3 · `docs/design/panel-spec.md` · `docs/design/search-spec.md`

## 결정 요약

| ID | 결정 | 근거 |
|---|---|---|
| D1 | **Astro + MDX + Content Collections** | 요구사항의 핵심 3가지(엄밀한 데이터 검증, MDX 컴포넌트, 스크롤/패널 인터랙션)를 1급으로 지원. 프론트매터 스키마를 Zod로 **빌드 시 강제**할 수 있고, 기본 JS 0KB + 필요한 곳만 island이므로 그래프/패널/검색 코드가 다른 페이지 성능을 해치지 않음. 이미지 최적화·Shiki 코드 하이라이팅 내장. Jekyll(참고 사이트 방식)은 위 3가지를 모두 우회 구현해야 하고 검증이 빌드에 강제되지 않음 |
| D2 | 루트(`/`) = **블로그 메인**, 포트폴리오 = `/portfolio/` | 블로그가 사이트의 중심이라는 요구를 URL 구조로도 드러냄 |
| D2-b | **B안 — 글 URL은 `/blog/<track>/<slug>/`** (격리) | 사이트 기능 경로와 완전 분리 → 예약어 충돌 위험 소멸, `robots.txt`·`sitemap`·분석 필터·캐시 규칙을 `/blog/*` 단위로 일괄 관리. 대가는 URL 한 단계 길어짐(무시 가능) |
| D3 | 그래프 연결 정보는 **프론트매터 선언 + 빌드 시 검증/레이아웃 생성** | 저작 시 파일 1개만 수정하면 되고 `related`는 자동 미러. 검증 규칙(R1~R15)으로 무결성을 빌드에서 강제. 좌표를 빌드 타임에 확정해 런타임 비용 제거 + git diff로 그래프 변화 추적 |
| D4 | 콘텐츠는 **신규 작성** | 이관 파서 비용 없이 샘플 2~3개로 구조를 먼저 검증한 뒤 증분 추가 |
| D5 | 도메인은 **`ppaong.github.io` 유지** (커스텀 도메인 미사용) | `public/CNAME` 불필요, `site` 값을 고정해 canonical/OG/sitemap을 단순하게 유지. 향후 전환은 CNAME+DNS 추가로 가능 |
| D6 | **검색 포함 — Pagefind 엔진 + just-the-docs UX 벤치마크** | 글 목록이 많아질 예정이므로 검색은 필수. UX는 just-the-docs(섹션 단위 결과·미리보기·단축키·검색 제외)를 목표로 하되, 엔진은 한국어 처리와 대량 인덱스 성능이 나은 Pagefind를 사용. 서버·계정·비용 없음 |
| D7 | 문서 내 목차는 **우측 패널 첫 탭** | 좌측 네비는 "사이트 + 트랙 트리"만 담당해 길이를 일정하게 유지 → 장문에서 탐색성 저하 방지. 패널을 "문서 안내 / 자료" 2탭으로 운영 |
| D8 | **Umami(오픈소스, 쿠키 없음) 도입**, GoatCounter 대안. M7 연결 | 무료로 시작 가능 + 오픈소스라 **자체 호스팅 이전 가능**(서비스 정책 변동에 대한 내성) + 콘텐츠 종류를 제한하는 약관 없음 + 쿠키가 없어 동의 배너 불필요 + 2KB 이하로 성능 예산 내 |

**미해결 항목 없음.** 나머지 세부는 `docs/design/*.md`와 M0~M7 마일스톤에서 다룬다.

## 검토했으나 채택하지 않은 대안

| 대안 | 기각 이유 |
|---|---|
| Jekyll + Lanyon 테마 | 스키마 검증·MDX 컴포넌트·island 단위 JS 격리를 모두 우회 구현해야 함. (Lanyon은 MIT이지만 스타일을 복사하지 않고 자체 토큰으로 재구현) |
| Next.js 정적 export | base path/설정 부담과 번들 크기 증가 |
| Hugo | MDX식 컴포넌트·스키마 검증에 불리 |
| **A안 — 글 URL을 루트(`/<track>/<slug>/`)에** | 짧은 URL 장점은 있으나 사이트 기능 경로와 네임스페이스를 공유해 예약어 검증·관리 부담이 생김. 루트를 향후 확장용 자유 공간으로 남기기 위해 기각 |
| **lunr.js (just-the-docs의 검색 엔진)** | 한국어 처리와 대량 인덱스 성능이 Pagefind보다 불리. **UX만 벤치마크**하고 엔진은 교체 |
| Fuse.js | 인덱스 전체를 JS로 전송 → 코퍼스가 커지면 부적합 |
| Algolia DocSearch | 외부 서비스·계정·크롤러 의존, 정책 변동 리스크 |
| **GA4** | 쿠키 사용(동의 배너 필요) + 50~100KB 스크립트 → 14장 성능·프라이버시 목표와 충돌 |
| `hits.seeyoufarm` 등 제3자 뷰 배지 | 프라이버시·성능·디자인 모두 불리 |
| 좌측 하단 문서 목차 / 본문 우측 여백 고정 목차 | D7로 기각 |
| 포트폴리오의 `scroll-snap`·WebGL | 모바일 이탈감·접근성·유지보수 비용 (CSS 연출 + 섹션 인디케이터로 대체) |
| 코드트리의 3D 눌림 버튼 효과 | 사이트 톤(절제)과 불일치 |
| 코드트리의 비율(%) 기반 패널 폭 | 우리 본문은 읽기용이라 **한 줄 길이가 일정해야** 함 → px 고정 + 드래그(320~560px)로 변형 |

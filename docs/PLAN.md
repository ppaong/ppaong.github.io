## 2. 참고 사이트 분석 (사실 근거)

### 2.1 모두를 위한 컨벡스 최적화

- 정적 사이트 생성기: **Jekyll** (`markdown: kramdown`, `plugins: jekyll-paginate`, `permalink: pretty`)
- 테마: **Lanyon** (Poole/Lanyon = MIT). 좌측 사이드바가 CSS 체크박스 `#sidebar-checkbox`로 토글되는 고전 패턴
- 본문 스타일: `github-markdown.css` + 좁은 단일 컬럼(`.container`, 약 38~44rem)
- 수식: MathJax 3를 **CDN에서 런타임 로드** (초기 렌더 비용 존재)
- 글 구조: `contents/chapterNN/YYYY/MM/DD/slug` 형태의 포스트 + 챕터 랜딩 페이지가 글 목록을 나열
- 목차: 그냥 표(table). **그래프/상호참조 개념 없음**
- 폰트: PT Serif / PT Sans (Google Fonts)

→ 우리가 가져올 것: **단일 좁은 컬럼, 절제된 색, 작은 대문자 메타, 얇은 구분선, 낮은 시각적 소음**.
→ 가져오지 않을 것: Lanyon CSS를 그대로 복사하지 않고 **자체 디자인 토큰으로 재구현**(유지보수·확장 목적).

### 2.2 코드트리

- React SPA(비공개). 우측 패널은 "본문과 보조자료를 동시에 보는" **레이아웃·동작**을 참고
- 사용자 제공 캡처(`docs/reference/codetree/`, 로컬 전용)에서 **실측값을 확보**했다
  - 2분할 `display:flex` + **비율(percentage) 기반** 패널 크기, 핸들 16px
  - 리사이즈 핸들이 `role="separator"` + `aria-valuemin/max/now` + `tabindex="0"` (**키보드 조절 가능**)
  - 헤더·푸터 각 **40px**, `rounded-12`, 본문 내 **sticky 서브헤더**(44px 안내 배너, 닫기 가능)
  - `contain: layout` + `overflow:hidden` 래퍼, `touch-action: pan-y`
  - 색 전환 **200ms ease-in-out**, 브레이크포인트는 `lg`/`max-md` 2단계만
  - 폰트가 **Pretendard Variable** (우리 6.2 선택과 일치)
- 채택/변형/배제 판단과 M3 수용 기준은 **`docs/design/panel-spec.md`** 에 정리
- 마크업·CSS를 그대로 복사하지 않고 자체 토큰으로 재구현 (저작권/유지보수 리스크 회피)

## 4. 사이트 구조 & 라우팅

```
/                        블로그 메인 (소개 + 트랙/강좌 안내 + 최근 글)   ← D2
/blog/toc/               목차 — 그래프 뷰 + 텍스트 목차 (탭 전환)
/blog/tracks/            전체 트랙 목록
/blog/<track>/           트랙(=강좌/시리즈) 랜딩: 설명 + 글 목록
/blog/<track>/<slug>/    본문 페이지
/portfolio/              포트폴리오 (스크롤 프레젠테이션)
/search/                 검색 (Pagefind)
/404
/rss.xml
/sitemap-index.xml
```

- **블로그 산출물은 전부 `/blog/` 접두어 아래**에 둔다 (D2-b = **B안**). 사이트 기능 경로와 섞이지 않아 트랙명·슬러그 충돌 위험이 사실상 없다.
- `src/content/blog/**`의 파일은 `track`/`slug` 프론트매터로 URL에 매핑된다. 콘텐츠 폴더 구조와 URL 구조는 독립이다.
- **예약어(R15)**: `blog`, `portfolio`, `search`, `assets`, `_astro`, `pagefind`, `404`, `rss.xml`, `sitemap-index.xml` — 트랙명·슬러그로 사용 금지(빌드 실패). B안이라 목록이 짧고 안정적이다.
- 운영 이점: `robots.txt`·`sitemap` 그룹핑, 분석 필터, 캐시 규칙을 **`/blog/*` 단위로 일괄 적용**할 수 있다.
- 참고: 네임스페이스 격리를 해제하고 루트로 옮기려면 라우트 접두어를 바꾸고 `/blog/*` → `/*` 리다이렉트를 생성하면 된다(전환 비용 낮음).

**URL 불변성 원칙 (중요)**
- 본문 URL은 **`/blog/<track>/<slug>/`** 로 고정한다.
- `slug`는 발행 후 **절대 변경하지 않는다.** 변경 시 `redirects` 맵에 반드시 등록한다.
- `id`(불변 식별자)와 `slug`(URL)를 분리한다. 제목이 바뀌어도 `id`/`slug`는 유지.
- GitHub User Pages이므로 `baseurl`은 `''`(루트). 모든 내부 링크는 절대경로 `/...`로 통일.

## 5. 정보 구조(IA) & 네비게이션

### 5.1 좌측 네비게이션 패널 (전역)

**2개 블록**으로 구성한다. (문서 내 목차는 우측 패널로 이동 — D7 확정)

1. **고정 블록**: 사이트명/로고 → 블로그 홈(`/`), 목차(그래프), 트랙 전체, 검색, 포트폴리오, 테마 토글
2. **트랙 트리 블록**: 트랙 → 글 목록(순서대로). 현재 글 하이라이트, 현재 트랙 자동 펼침. 자체 스크롤

- 현재 문서의 `h2/h3` 목차와 scrollspy는 **우측 패널의 첫 탭**에서 제공한다(9.3).
- 좌측은 "사이트 + 트랙"만 담당해 길이를 일정하게 유지한다(장문에서 탐색성 저하 방지).

**동작 스펙**
- 펼침/접힘 상태, 마지막 섹션 상태를 `localStorage`에 저장
- 모바일(<1024px): 오프캔버스 드로어 + 오버레이. ESC/오버레이 클릭/스와이프로 닫기, **포커스 트랩**, 열림 시 배경 스크롤 락
- 키보드: `[` 네비 토글, `]` 자료 패널 토글, `/` 검색 포커스 (단축키는 도움말에 명시)
- 스킵 링크("본문으로 건너뛰기") 제공

### 5.2 헤더/브레드크럼

- 본문 페이지 상단: `블로그 / <트랙명> / <현재 글 제목>` 브레드크럼
- 우측 자료 패널 토글 버튼은 **헤더 우측 상단에 고정**

## 6. 디자인 시스템 (스타일 가이드)

### 6.1 원칙

1. **저소음**: 색은 본문/링크/경고 계열 3~4개만. 악센트 색 1개
2. **읽기 우선**: 본문 최대 폭 44rem 내외, 줄간격 1.75, 한글 기준 자간 0
3. **일관성**: 모든 값은 CSS 변수(디자인 토큰)로만 사용. 하드코딩 금지
4. **다크 모드**: `prefers-color-scheme` 자동 + 수동 토글 + 저장

### 6.2 타이포그래피

| 용도 | 권고 | 비고 |
|---|---|---|
| 본문 한글 | **Pretendard**(가변 폰트, OFL) | 자체 호스팅, `font-display: swap` |
| 본문 라틴/숫자 | 본문과 동일 또는 Source Serif | 컨벡스 사이트는 Serif 계열 → 선택 가능 |
| 제목 | 본문과 같은 패밀리, 굵기/크기로 위계 | 폰트 수 최소화 |
| 코드 | JetBrains Mono 또는 D2Coding | |

타입 스케일: 12 / 14 / 16 / 18 / 20 / 24 / 30 / 38 (rem 기반, 16px 기준)

### 6.3 토큰 초안

```css
:root {
  --color-bg, --color-surface, --color-text, --color-text-muted,
  --color-border, --color-accent, --color-accent-weak,
  --color-warn, --color-code-bg,
  --space-1..--space-8,
  --radius-sm/md/lg,
  --shadow-1/2,
  --layout-nav, --layout-panel, --layout-prose,
  --duration-fast/base, --ease-out
}
```

### 6.4 브레이크포인트 & 3컬럼 전략

| 구간 | 좌 네비 | 본문 | 우 자료 패널 |
|---|---|---|---|
| ≥1440px | 260px 고정 | 중앙, max 720px | 380px 고정, 스티키 |
| 1024–1439px | 240px (접기 가능) | 유동 | 320px (접기 가능) |
| 768–1023px | 드로어 | 전폭(max 720 중앙) | 오버레이 패널(우측 시트) |
| <768px | 드로어 | 전폭 | **바텀 시트**(아래에서 올라옴, 드래그로 높이 조절) |

- 좌/우 패널 폭은 **드래그 리사이즈** 지원, 값 저장 (우측 패널 우선)
- **우측 패널 폭은 px 고정 + 드래그(320~560px)** 로 결정한다. 비율(%) 방식은 본문 한 줄 길이가 흔들려 가독성을 해치기 때문이다. 키보드 조절·클램프·리셋 규칙은 `docs/design/panel-spec.md` 2.1 참조
- 좌우 패널 모두 접으면 **집중 모드(zen)**: 본문만 남김
- **1024px 미만에서는 좌 네비와 우 패널을 동시에 열지 않는다**(한 번에 하나만). 좁은 화면의 3컬럼은 가독성을 해친다

### 6.5 수식 / 코드

- 수식: **KaTeX + rehype-katex로 빌드 타임 렌더** (MathJax 대비 초기 렌더 비용 절감). 화학식 등 특수 요구가 생기면 해당 페이지만 MathJax 허용
- 코드: **Shiki 빌드 타임 하이라이팅**, 복사 버튼, 파일명 라벨, 줄 강조(`{3,5-7}`), diff 표시, (선택) 줄 번호

## 7. 블로그 메인 페이지 (`/`) — 사이트 루트 · D2

구성(위→아래)

1. 블로그 소개 (2~3문장) + 대표 이미지/로고
2. **트랙(강좌) 카드 목록**: 트랙명, 한 줄 설명, 난이도, 글 수, 예상 소요, 진행률(선택), CTA
3. **시작하기 가이드**: "처음이라면 이 3개 글을 순서대로" (그래프에서 뽑은 추천 입문 경로)
4. 최근 업데이트 글 5개 + 전체 목차 링크
5. 검색 진입, RSS 링크

데이터는 전부 트랙 정의(`src/data/tracks.ts`)와 콘텐츠 컬렉션에서 **자동 파생**한다. 손으로 목록을 쓰지 않는다(누락 방지).

## 8. 목차(그래프) 페이지 — **핵심 설계**

### 8.1 개념 정의

- **노드** = 본문 페이지 1개 (보조 노드로 "트랙" 그룹 박스 허용)
- **간선** = 방향 있음. **의미를 하나로 고정한다:
  `A → B` = "A를 먼저 접한 뒤 B로 진행하는 것이 학습상 자연스럽다"**
- 간선은 두 **레이어**로 나눈다.

**레이어 1 — 교육과정(curriculum)**: 실제 학습 순서를 만든다. 이 레이어는 **DAG(비순환)를 강제**한다.

| kind | 의미 | 방향 | 비고 |
|---|---|---|---|
| `sequence` | 트랙 내 다음 글 | 트랙 `order`에서 **자동 생성** | 손으로 선언 금지 |
| `requires` | 선수 개념 | 강한 의존 | 순환 금지 |
| `applies` | 개념 → 응용 | 강한 의존 | 순환 금지 |

**레이어 2 — 주석(annotation)**: 학습 순서를 만들지 않는다. 순환 허용.

| kind | 의미 | 방향 |
|---|---|---|
| `related` | 연관(대칭) | 양방향으로 표시 |
| `cites` | 서지적 인용/출처 | 비대칭 |
| `supersedes` | 구버전 → 신버전 | 비대칭 |

- **방향 표기 규칙**: 화살표 머리는 "나중"을 가리킨다. 화면에는 `선수 ← 현재 → 후속` 칩으로도 병기해 방향을 색/모양에만 의존하지 않게 한다.

### 8.2 데이터 원천 & 빌드 파이프라인

```
content/*.mdx frontmatter
        │  (선언)
        ▼
[1] validate-content  ── 스키마/무결성 검사 (오류 시 빌드 실패)
        ▼
[2] build-graph       ── 정규화 + 좌표 계산 (elkjs layered, 결정적 정렬)
        ▼
   graph.json  (nodes[].x/y/w/h, edges[], tracks[])
        ▼
[3] GraphView island  ── 정적 SVG 렌더 + 인터랙션만 JS
```

- 좌표를 **빌드 타임에 확정**하고 `graph.json`으로 커밋 가능하게 둔다 → 런타임은 레이아웃 연산이 없어 빠르고, **git diff로 그래프 변화를 추적**할 수 있다(엄밀성 확보).
- 레이아웃 엔진: `elkjs`의 `layered` 알고리즘, `direction: DOWN`, 노드 정렬은 `track` → `order` 순으로 **결정적** 정렬(같은 입력 = 같은 출력).
- 수동 보정: `src/data/graph.overrides.ts`에서 특정 노드 좌표 고정(pin) / 그룹 박스 지정 / 엣지 숨김. 자동 레이아웃이 마음에 안 들 때만 사용.

### 8.3 검증 규칙 (CI에서 빌드 실패/경고)

| ID | 규칙 | 수준 |
|---|---|---|
| R1 | 프론트매터가 스키마를 만족 | **오류** |
| R2 | `id` 전역 유일, `slug` 전역 유일 | **오류** |
| R3 | 링크 대상 `id`가 실재 (dangling 금지) | **오류** |
| R4 | 자기 참조 금지 | **오류** |
| R5 | curriculum 레이어 비순환 (DAG) | **오류** |
| R6 | 트랙 내 `order` 중복 금지 | **오류** |
| R7 | `sequence`가 `order`와 모순되지 않음 | **오류** |
| R8 | `related` **역방향 선언 누락** — 그래프 빌더가 자동 미러하므로 경고로 처리 | 경고 |
| R9 | `materials[].id` 페이지 내 유일 + 본문 참조(`<FigureRef>`)가 실존하고 **`n` 번호가 배열 순서와 일치** | **오류** |
| R10 | `draft`는 배포 그래프에서 제외, 로컬에서는 포함 | **오류** |
| R11 | 트랙에 속하지만 아무 간선도 없는 고아 노드 | 경고 |
| R12 | 트랙 정의(`tracks.ts`)와 노드의 `track` 일치 | **오류** |
| R13 | 외부 URL HTTP 상태 (링크 체크) | 경고 |
| R14 | 이미지 `alt` 누락, 이미지 파일 용량 상한(예: 1.5MB) 초과 | 경고 |
| R15 | `track`/`slug`가 **예약어**와 충돌하지 않음 (4장 목록, D8 도입 시 `privacy` 추가) | **오류** |

### 8.4 인터랙션 스펙

- 팬/줌(휠·핀치·버튼), 리셋, 전체화면
- 호버: 노드 카드 미리보기(제목/트랙/난이도/요약), 연결 간선 강조
- 클릭: 해당 글로 이동
- **포커스 모드**: 선택 노드 기준 n-hop(1~3)만 강조, 나머지 dim. `hops` 조절 UI
- 필터: 간선 kind 토글, 트랙 토글, 난이도/태그 필터
- **학습 경로 탐색**: 두 글을 고르면 curriculum 레이어 최단 경로를 강조 → "이 순서로 읽으세요"
- **LOD(세부 수준)**: 줌 아웃 시 트랙 그룹 박스만 표시, 줌 인 시 개별 노드 노출 (노드 수 증가 대응)
- 미니맵(노드 50개 초과 시), 노드 수 100개 초과 시 **트랙별 분할 뷰** 권장
- 상태는 URL 쿼리로 직렬화: `?focus=algo-dp-01&hops=2&kinds=requires,sequence&tracks=algorithms` → **공유 가능한 링크**

### 8.5 텍스트 목차 (필수 병행 제공)

- 그래프 페이지 내 **탭: [그래프] [텍스트]**, 그리고 그래프를 못 쓰는 환경에서는 텍스트가 기본
- 텍스트 뷰: 트랙별 중첩 리스트 + 각 항목에 `선수/후속` 칩 + 접기/펼치기 + 검색 필터
- 추가로 **인접 리스트(adjacency) 표 뷰** 제공: 각 글의 `선수 / 후속 / 관련`을 표로 나열 (그래프를 선형적으로 읽고 싶은 사용자용)
- JS 없이도 전체 목록에 도달 가능해야 한다 (SSR 정적 HTML)

### 8.6 접근성

- 그래프 SVG는 `role="img"` + `aria-label`에 요약(노드 수/트랙 수) 제공, 상세는 텍스트 목차가 담당
- 노드 키보드 내비게이션: roving tabindex, 방향키 이동, Enter 이동, Esc 해제
- 간선 종류를 **색만으로 구분하지 않음** — 점선 패턴 + 범례 라벨 병기
- `prefers-reduced-motion: reduce` 시 전환 애니메이션 제거
- 대비 4.5:1 이상

### 8.7 성능

- 그래프 페이지에서만 island 로드(다른 페이지 JS 영향 0). 목표: 그래프 페이지 JS ≤ 120KB gzip
- SVG 노드 500개까지 목표. 초과 시 canvas 렌더로 전환 (인터페이스는 동일하게 유지)

## 9. 본문 페이지 (`/<track>/<slug>/`)

### 9.1 상단

- 브레드크럼(5.2)
- `h1` 제목
- 메타 라인: 트랙, 순서 `n / m`, 난이도, 태그, 최초 작성일/최종 수정일, 읽기 시간(자동 계산), 상태(초안 뱃지)
- (선택) 요약문 1~3줄

### 9.2 본문 영역 (좌측·중앙)

- 마크다운/MDX 프로즈, `h2/h3` 앵커 링크, 스크롤스파이
- 마지막에 **이전 글 / 다음 글** 카드 + "이 글에서 참조한 개념 / 이 글을 참조하는 글" 목록(그래프에서 자동 파생)
- 하단: 목차(그래프)로 돌아가기, 트랙 랜딩 링크, 피드백(이슈 템플릿 링크)

### 9.3 우측 패널 (문서 안내 + 보조자료) — **핵심 설계**

**목적**: (1) 긴 글에서 위치를 잃지 않도록 **문서 내 목차**를 제공하고, (2) 본문을 읽으면서 **이미지/참고자료를 동시에** 본다. 페이지 이동 없이 참조.

**패널 구조 (2계층 탭)**

| 탭 | 내용 | 기본값 |
|---|---|---|
| 1. 문서 안내 | 현재 문서의 `h2/h3` 목차 + scrollspy 활성 표시 | **기본 탭** (D7 확정). 목차가 없는 짧은 글은 자료 탭이 기본 |
| 2. 자료 | `materials[]`를 `group`별로 묶어 표시 (예: 개념도 / 데이터 / 참고문헌) | 자료가 없으면 탭 자체를 숨김 |

- 패널 헤더에 현재 문서 제목을 표시하고, 탭/그룹 전환 상태를 `localStorage`에 저장한다.
- 구현 상세(코드트리 실측값, 채택/변형/배제 판단, M3 수용 기준 10항목)는 **`docs/design/panel-spec.md`** 참조

**자료 항목 스키마** (`materials[]`)

| 필드 | 설명 |
|---|---|
| `id` | 본문에서 참조하는 키 (페이지 내 유일) |
| `type` | `image` \| `gallery` \| `pdf` \| `video` \| `code` \| `link` \| `note` |
| `title` | 패널에 표시할 제목 |
| `caption` | 캡션/설명 |
| `alt` | **필수**(image) |
| `src`/`href` | 경로 |
| `group` | 패널 내 그룹(탭) — 예: `개념도`, `데이터`, `참고문헌` |
| `source` | 출처/라이선스 표기 |

**동작 스펙**

1. **토글**: 헤더 버튼/`]` 키/스와이프. 열림·닫힘, 폭, 마지막 활성 그룹/항목을 `localStorage`에 저장
2. **양방향 동기화**
   - 본문의 `<FigureRef id="fig-1">` 클릭 → 패널이 닫혀 있으면 열고, 해당 그룹으로 전환 후 항목 하이라이트 + `scrollIntoView`
   - 패널 항목 클릭 → 본문의 해당 참조 위치로 스크롤(옵션으로 끄기 가능)
3. **접힌 상태에서도 존재감**: 본문 우측 여백에 참조 마커를 남겨 "패널에 자료가 있음"을 인지시킴
4. **이미지 UX**: 클릭 시 라이트박스(확대/축소/원본 보기/다운로드), 키보드 좌우 이동
5. **그룹 탭**: 자료 탭 내부에서 `group`별 탭. 그룹이 없으면 단일 스크롤
6. **성능**: 지연 로딩 + `width/height` 명시(CLS 방지) + `srcset`
7. **인쇄**: `print.css`에서 패널 자료를 **부록으로 본문 뒤에 펼쳐 출력**
8. **모바일**: 바텀 시트. 드래그로 높이 조절, 최대 화면 90%

**저작 편의(MDX)**

```
<Figure id="fig-dp-table" caption="중복 부분문제 표">…</Figure>
<MaterialLink id="ref-tabulation">표 채우기 방식 보기</MaterialLink>
```

`Figure`는 본문에 작은 썸네일을 넣고 **확대본을 패널에 자동 등록**하는 모드도 지원한다(같은 파일을 두 번 쓰지 않게).

### 9.4 그 외

- `draft` 글은 로컬에서만 보이고 배포물에는 없음 (`status`로 제어)
- 목차 없는 짧은 글도 동일 레이아웃 사용(패널만 비게 됨)

## 10. 포트폴리오 페이지 (`/portfolio/`)

### 10.1 섹션 구성(세로 스크롤)

1. **Hero**: 이름, 한 줄 소개, 스크롤 유도, 대표 링크(깃허브/이메일/블로그)
2. **한 줄 소개 / About**: 3~5줄 이내(명함 수준 원칙 준수)
3. **Skills / Stack**: 짧은 태그 나열
4. **Projects**: 카드 3~5개. 클릭 시 관련 블로그 글로 연결(블로그 유도)
5. **Timeline**: 활동/이력 간략
6. **Contact**: 이메일, 깃허브, 링크드인, **이력서 PDF 다운로드**
7. 블로그로 가는 강한 CTA

### 10.2 연출 스펙

- `position: sticky` + `IntersectionObserver` 기반 페이드/슬라이드. **transform/opacity만 애니메이션**(성능)
- `scroll-snap`: 기본 **사용 안 함**(모바일/트랙패드에서 이탈감·접근성 문제). 대신 **섹션 인디케이터(점/진행바)**로 프레젠테이션 느낌 확보
- 패럴랙스는 최소한. WebGL/3D는 관리비용·접근성 때문에 **배제**
- `prefers-reduced-motion: reduce` 시 모든 등장 애니메이션 제거(정적 스택)
- JS 비활성 시에도 모든 콘텐츠가 순서대로 읽힘(점진적 향상)
- 히어로 배경은 이미지를 쓰더라도 LCP 이미지 1장 이하, AVIF/WebP

### 10.3 관리

- 포트폴리오 내용도 MDX/데이터 파일로 관리(HTML 하드코딩 금지) → 수정이 쉽고 검증 가능

### 13.2 M0에서 확정한 구현 사실

- 다크 모드는 **CSS `light-dark()` + `color-scheme`** 으로 구현 → 다크 값을 한 번만 정의하고, `[data-theme]`(수동 토글)과 `prefers-color-scheme`(JS 없음)을 동시에 지원
  - 이에 따라 **브라우저 기준을 iOS Safari 17.5+ / Chrome 123+ / Firefox 120+ 로 상향** (14장 참조)
- 테마 확정 스크립트는 `is:inline`으로 `<head>`에서 실행 → **FOUC(깜빡임) 없음**
- 좌측 네비게이션 데이터(`SITE.NAV`)에 `status: 'ready' | 'planned'`를 두어 **아직 없는 경로를 링크하지 않는다**(404 방지). 페이지를 만들면 `ready`로 전환
- 빌드 결과: 페이지 2개(`/`, `/404.html`), **JS 0KB**(인라인), CSS 8KB

### 13.3 M1에서 확정한 구현 사실

- **3컬럼 셸**: `.app-shell`은 CSS Grid `var(--nav-w) minmax(0,1fr) var(--panel-w)` 한 줄로 구성하고, 접힘/펼침은 **커스텀 프로퍼티만 바꿔** 처리한다(`data-nav` / `data-panel`). 상태 조합이 늘어나도 규칙이 곱해지지 않는다
- **폭이 0으로 접힐 때**: 패널에 `overflow: hidden`, 내부 래퍼에 `min-width: var(--layout-nav | --layout-panel)`을 주어 전환 중 내용 리플로우를 막는다
- **우 패널 폭은 `--panel-current`로 덮어쓸 수 있게** 설계 → M3의 드래그 리사이즈가 이 변수만 갱신하면 된다 (panel-spec 2.1)
- **모바일(<1024px)**: 좌 nav = 드로어, 우 패널 = 우측 시트(768px 미만은 **바텀 시트**). 이때 JS가 `data-nav`/`data-panel`을 **제거**해 데스크톱 가시성 규칙과의 명시도 충돌을 원천 차단한다
- **접근성**: 패널이 닫히면 `inert` 부여(포커스·스크린리더 차단), 토글에 `aria-expanded`, 오버레이에 스크림 + 배경 스크롤 락
- **집중 모드**: `[`로 좌 nav, `]`로 우 패널 토글(`CapsLock`·한글 입력 상태에서도 `event.key`가 `[`/`]`로 들어오는 것을 확인해야 함 → 미검증 항목)
- 상태 저장 키: `shell.nav` / `shell.panel` (모바일 오버레이는 저장하지 않음 — 화면이 작으면 항상 닫힘으로 시작)
- 미디어쿼리는 Lightning CSS가 **range 문법**(`@media (width<=1023.98px)`)으로 출력 → 브라우저 기준(iOS Safari 17.5+) 내

### 13.4 M2에서 확정한 구현 사실

- **⚠️ Astro 7의 Markdown 프로세서**: 기본값이 Rust 기반 **Sätteri**로 바뀌었다. remark/rehype 생태계(KaTeX)를 쓰려면 `@astrojs/markdown-remark`의 `unified()`를 **명시적으로 선택**해야 한다.
  ```js
  import { unified } from '@astrojs/markdown-remark';
  markdown: { processor: unified({ remarkPlugins: [remarkMath], rehypePlugins: [rehypeKatex] }) }
  ```
  `markdown.remarkPlugins` 직접 지정은 deprecated(경고만, 동작은 함). **Sätteri를 쓰면 빌드는 빠르지만 생태계 플러그인을 포기해야 한다**
- **파일 경로 = 식별자**: `src/content/blog/<track>/<slug>.mdx` → `entry.id` = `<track>/<slug>` → URL `/blog/<track>/<slug>/`. 프론트매터에 `track`/`slug`를 중복 기재하지 않는다
- **자료 번호(`n`) 규약**: `materials` 배열 순서가 곧 패널 번호이고, 본문 `<FigureRef n={..}>`와 일치해야 한다 → **검증 스크립트가 강제**(R9)
- **검증 스크립트는 TypeScript로 작성**(`scripts/validate-content.ts`). Node 22.6+ 의 타입 스트리핑 덕분에 **별도 빌드 없이** `src/data/*.ts`를 그대로 import해 검증할 수 있다
- **KaTeX 표기 주의**: MDX에서 중괄호는 특별 문자이므로 집합 기호는 `\lbrace`/`\rbrace`를 쓴다(`authoring.md` 3.1)
- 우측 패널 기본 상태는 **열림**(6.4의 "≥1024px에서 함께 열어 둔다" 기본값). 본문의 `<FigureRef>` 클릭은 `open-panel` 커스텀 이벤트로 셸에 전달된다
- 글 작성 방법은 **`docs/authoring.md`** 에 정리(프론트매터 표, 수식, 자료 타입별 필드, 발행 절차, 체크리스트, 자주 하는 실수)

## 15. 배포 & 저장소

- `ppaong.github.io`는 **User Pages** → URL 루트가 `/`. `baseurl=''`
- Repo Settings → Pages → **Source: GitHub Actions**
- `deploy.yml`: `npm ci` → `npm run build` → `upload-pages-artifact` → `deploy-pages`
  (`permissions: contents: read, pages: write, id-token: write`, `concurrency` 설정)
- Node 22 LTS 고정(`.nvmrc`), npm 캐시 사용
- 브랜치: `main`(배포) / `content/*`(글) / `feat/*`(기능). `main` 보호 규칙 + PR 필수
- **커스텀 도메인 미사용 (D5 확정)** → `public/CNAME` 불필요, `site: 'https://ppaong.github.io'` 고정
- 향후 커스텀 도메인으로 전환할 경우: `public/CNAME` 추가 + DNS A/AAAA(또는 CNAME) 설정 + HTTPS 강제. 전환 시 `site` 값 변경만으로 canonical/OG/sitemap이 일괄 갱신됨
- PR 프리뷰는 GitHub Pages가 미지원 → 필요하면 Cloudflare Pages 프리뷰 병행(선택)

# 부록 A — URL 네임스페이스 (D2-b) 상세

## A.0 무엇을 정하는 문제인가

글 하나의 URL을 이렇게 둘지, 저렇게 둘지의 문제다.

- **A안(루트)**: `https://ppaong.github.io/algorithms/dp-intro/`
- **B안(격리)**: `https://ppaong.github.io/blog/algorithms/dp-intro/`

"track"은 강좌/시리즈 이름(`algorithms`, `math`, …), "slug"는 글 이름이다. 블로그 메인은 이미 `/`(루트)로 정했기 때문에, 그 아래에 글을 두는 방식에 두 가지 선택지가 생긴다.

## A.1 항목별 비교

| 항목 | A안: `/<track>/<slug>/` | B안: `/blog/<track>/<slug>/` |
|---|---|---|
| URL 길이·가독성 | 짧고 외우기 쉬움 | 한 단계 길다 |
| 의미 전달 | "이 사이트 = 블로그" 일관 | "블로그는 사이트의 한 영역" 명확 |
| 최상위 경로 충돌 위험 | **있음** (트랙명과 사이트 페이지명이 겹칠 수 있음) | `/blog/`만 예약 → 사실상 없음 |
| R15 예약어 검증 | **필수** | 거의 불필요 |
| 사이트 영역을 새로 추가할 때 | 예약어 목록을 갱신해야 함 | 자유로움 |
| 브레드크럼 | 홈 > 트랙 > 글 | 블로그 > 트랙 > 글 |
| sitemap·robots·분석 필터링 | 접두어가 없어 분류가 번거로움 | `/blog/*`로 일괄 처리 |
| SEO | 미세하게 유리(짧은 경로) | 미세하게 불리(**실질 차이 거의 없음**) |
| 트랙 이름 변경 비용 | URL 변경 → 리다이렉트 필요 | 동일 |
| 향후 서브도메인 분리 | 리다이렉트 필요 | 동일 |
| GH Pages 루트 배포와의 궁합 | 자연스러움 | 자연스러움 |

## A.2 A안의 구체적 위험

A안은 "최상위 경로를 사이트 페이지와 나눠 쓴다"는 것이 유일한 약점이다. 실제로 충돌할 수 있는 이름은 이 정도다.

- 사이트 기능: `portfolio`, `toc`, `tracks`, `search`, `about`, `tags`, `privacy`, `404`, `rss.xml`, `sitemap-index.xml`
- 빌드 산출물: `assets`, `_astro`, `pagefind`, `images`
- 만약 트랙 이름을 `notes`, `projects`, `blog`, `about` 처럼 짓고 싶어지면 충돌한다

대응은 명확하다.
1. `src/data/reserved.ts`에 예약어를 **한 곳에서** 관리
2. 빌드 시 트랙명/슬러그가 예약어와 충돌하면 **빌드 실패**(R15)
3. 트랙은 발행 후 이름을 바꾸지 않는 것을 원칙으로 함

이 3가지를 지키면 A안의 위험은 "빌드가 막아주는 실수" 수준으로 내려간다. 반대로 이 규율을 지킬 자신이 없거나, 앞으로 **사이트 영역을 5개 이상** 만들 계획이면 B안이 낫다.

## A.3 판단 기준 (예/아니오)

| 질문 | 예 → |
|---|---|
| 트랙 이름을 영문 소문자 고정어(`algorithms`, `math`, `web`)로 유지할 수 있는가 | A안 안전 |
| 앞으로 `about`, `projects`, `uses`, `tags`, `privacy` 등 글 외 페이지를 5개 이상 만들 것인가 | B안 |
| URL을 손으로 입력하거나 QR로 공유할 일이 많은가(교육 자료 배포) | A안 |
| 주제별로 여러 개의 루트 섹션을 운영하고 싶은가 | B안 |

## A.4 "지금 정하지 않으면 큰일 난다"는 오해 정정

- Astro에서는 **리다이렉트를 콘텐츠 컬렉션에서 자동 생성**할 수 있다. A안 → B안으로 바꾸면 `/x/y/` → `/blog/x/y/` 리다이렉트를 스크립트 20줄로 만들어 영구히 유지할 수 있다.
- 따라서 전환 비용은 "스크립트 작성 + 재배포" 수준이고, 검색엔진 색인·외부 백링크도 리다이렉트로 승계된다.
- 그래도 **한 번 정한 canonical URL은 되돌리지 않는 것**이 원칙이다(중복 URL 누적 방지).

## A.5 결론 — **B안 채택** (확정)

> **결정: B안 `(/blog/<track>/<slug>/)`.** 네임스페이스를 `/blog/`로 격리해 사이트 기능 경로와 완전히 분리한다.
> 근거: 예약어 검증 부담이 사라지고, `robots.txt`·`sitemap`·분석 필터·캐시 규칙을 `/blog/*` 단위로 일괄 관리할 수 있다.
> 대가는 URL 한 단계 길어짐(무시 가능)과 "메인은 `/`, 글은 `/blog/`"의 약간의 비대칭이다.
> A안의 장점(짧은 URL)은 포기하되, 루트를 사이트의 자유 공간으로 남겨 향후 확장성을 확보한다.
> 단, **①`reserved.ts` 단일 관리, ②트랙 slug 발행 후 불변, ③사이트 영역 추가 시 같은 PR에서 예약어 갱신** 이 3가지를 규칙으로 확정할 때만 A안을 택한다.

# 부록 B — 검색 (D6) 상세

## B.0 무엇인가

**Pagefind**는 정적 사이트 전용 검색 라이브러리다. 빌드가 끝난 뒤 `dist/`의 HTML을 읽어 **검색 인덱스를 파일로 생성**하고, 사용자가 검색할 때 그 파일을 브라우저에서 읽어 결과를 만든다.

```
npm run build  →  npx pagefind --site dist  →  dist/pagefind/*  (인덱스 + WASM + 소형 JS)
```

- 서버·DB·계정·API 키가 **필요 없다**
- GitHub Pages 같은 정적 호스팅에서 그대로 동작
- 검색은 사용자 브라우저 안에서 수행 → 검색어가 외부로 전송되지 않음

## B.1 장점

| 장점 | 설명 |
|---|---|
| 비용·운영 부담 0 | 무료, 서버 없음, 관리할 인프라 없음 |
| 성능 | 검색 UI를 열 때만 인덱스 청크를 내려받음 → **본문 페이지 성능에 영향 없음** |
| 정확한 인덱싱 대상 | 빌드된 HTML을 읽으므로 MDX가 렌더한 최종 텍스트·캡션·표까지 포함 |
| 우리 IA와 궁합 | `data-pagefind-filter`로 **트랙·태그 필터** 검색 가능 |
| 한국어 지원 | 다국어 인덱스 지원. 한글 본문 검색 가능 |
| 접근성·UX 기본기 | 결과 하이라이트, 키보드 조작, 디자인 커스터마이징 자유 |
| 프라이버시 | 검색어가 서버로 가지 않음 |

## B.2 단점·한계

| 한계 | 설명 | 대응 |
|---|---|---|
| 형태소 분석이 아님 | `동적계획법` vs `동적 계획법`처럼 **띄어쓰기 차이로 누락**될 수 있다 | 제목·태그 표기를 일관되게, 동의어 보강, 필요 시 부분일치 모드 |
| 오타 교정 없음 | `알고리즘`을 `알고리듬`으로 치면 못 찾음 | 한계로 수용 (Algolia만 가능) |
| 인덱스 용량 | 글이 300편 이상이면 수 MB | 청크 분할로 완화. 초기 로딩 약간 증가 |
| 빌드 단계 추가 | CI에 pagefind 실행 추가 → 빌드 시간 소폭 증가 | 캐시로 완화 |
| UI를 직접 만들어야 함 | 스타일·키보드·`/search/` 라우트·빈 결과 처리 | 디자인 토큰으로 재구현 (반나절) |
| JS 필수 | no-JS 환경에서는 검색 불가 | **텍스트 목차/트랙 트리로 대체 동선 제공** |
| 검색어 로그 없음 | 인기 검색어를 알 수 없음 | 필요하면 분석 도구 이벤트로 별도 전송(부록 C) |
| 그래프 SVG는 미인덱싱 | 그래프 노드는 검색 대상이 아님 | 텍스트 목차가 인덱싱되므로 실질 문제 없음 |

## B.3 대안 비교

| 방식 | 서버/비용 | 한국어 품질 | 번들 부담 | 유지보수 | 비고 |
|---|---|---|---|---|---|
| **Pagefind** | 없음/무료 | 양호(형태소 X) | 필요할 때만 | 낮음 | 권장 |
| Fuse.js + JSON | 없음/무료 | 보통 | **인덱스 전체를 JS로 전송 → 큼** | 낮음 | 소규모에만 |
| Lunr | 없음/무료 | 약함 | 큼 | 낮음 | 한국어 불리 |
| Algolia DocSearch | 외부(문서 사이트 무료 신청) | 최상 | 작음 | 계정·크롤러 의존, 정책 변동 리스크 | 오픈소스 문서 프로젝트 아니면 승인 불확실 |
| 검색 없음 | - | - | 0 | 0 | 목차 그래프+트랙 트리로 대체 |

## B.4 결론 — **포함 채택** (확정)

> **결정: M5에 포함.** 글 목록이 많아질 예정이므로 검색은 필수 기능으로 본다.
> UX는 **just-the-docs**의 검색 체계(섹션 단위 결과, 미리보기, 키보드 단축키, 검색 제외 설정)를 목표로 한다.
> 다만 엔진은 lunr가 아니라 **Pagefind**를 쓴다 — 한국어 처리와 대량 인덱스 성능에서 유리하다.
> 최소 요구: **①좌측 네비 검색창, ②`/search/?q=` 결과 페이지, ③트랙/태그 필터, ④키보드 조작(`⌘K`·`/`), ⑤빈 결과 안내, ⑥no-JS 시 텍스트 목차 링크 제공**.

# 부록 C — 분석 (D8) 상세

## C.0 전제: GitHub Pages는 서버 로그를 주지 않는다

정적 호스팅에는 접근 로그가 없다. 즉 **분석 도구를 붙이지 않으면 어떤 지표도 남지 않는다.** 이것이 이 결정의 핵심이다. (컨벡스 최적화 사이트가 `hits.seeyoufarm` 같은 배지로 뷰 수를 세던 이유가 이것이다.)

## C.1 먼저 정할 것 — 무엇을 알고 싶은가

| 목표 | 필요한 기능 |
|---|---|
| 어떤 글이 읽히는가 | 페이지뷰(글별) |
| 독자가 어디서 이탈하는가 | 스크롤 깊이·체류 시간(이벤트) |
| 독자가 어떤 주제를 원하는가 | **검색어 이벤트** (콘텐츠 갭 발견) |
| 자료 패널을 실제로 쓰는가 | 패널 토글 이벤트 (우리 사이트만의 인사이트) |
| 어디서 유입되는가 | 리퍼러 |
| 포트폴리오가 설득력이 있는가 | 이력서 다운로드 / 연락 클릭 |

## C.2 선택지 비교

| 도구 | 비용 | 쿠키 | 스크립트 | 동의 배너 | 비고 |
|---|---|---|---|---|---|
| **Umami** | 자체호스팅 무료 / 클라우드 무료 티어 | 없음 | ~2KB | 불필요 | 오픈소스, 커스텀 이벤트 지원 |

| 없음 | - | - | 0 | - | 지표 0 |

## C.3 장단점

**도입 장점**
- 인기 글·이탈 지점을 보고 **어떤 트랙을 확장할지** 데이터로 결정 (교육 블로그에서 가치가 크다)
- 검색어로 **콘텐츠 갭** 발견
- 포트폴리오 → 블로그 → 연락/이력서로 이어지는 전환을 측정

**도입 단점**
- 서드파티 스크립트 의존 → 성능 예산 소모(2KB+), CSP 관리 필요
- 프라이버시 고지 필요 (쿠키 없는 도구면 부담이 매우 적음)
- 자체호스팅 시 유지보수 부담(업데이트·백업·도메인)
- 지표에 끌려 본래 목적(좋은 글 쓰기)이 흔들릴 수 있음

**GA4를 피하는 이유**
- 쿠키 사용 → 동의 배너 필요 → 사이트 첫인상 훼손
- 50~100KB 스크립트 → 14장 성능 목표와 직접 충돌
- 데이터가 구글에 귀속됨

**미도입의 장단점**
- 장점: 성능·프라이버시·유지보수 최소, 도구 종속 없음
- 단점: 무엇이 읽히는지 전혀 모름, 검색어 인사이트 상실

## C.4 결론 — **Umami 채택** (확정)

> **결정: 무료·쿠키 없음 도구로 도입. Umami(오픈소스) 1순위, GoatCounter 대안.**
> "무료 + 장기 사용 + 글 내용에 제약이 없는" 조건을 만족하는 이유:
> 1. **무료 티어로 시작 가능**(Umami Cloud) 2. **오픈소스라 자체 호스팅으로 이전 가능** → 서비스 정책이 바뀌어도 데이터·기능을 잃지 않음 3. 콘텐츠 종류를 제한하는 약관이 없음 4. 쿠키가 없어 **동의 배너·개인정보 동의 절차가 불필요** 5. 스크립트 2KB 이하로 성능 예산 내
> GA4는 무료이지만 쿠키·동의 배너·50~100KB 스크립트 때문에 **미채택** (14장 성능 목표와 직접 충돌).
> 도입 시점: **M7**(마감). 필수 이벤트 4개만 정의하고 과계측하지 않는다.

**과계측 금지 — 이벤트 4개만** 정의한다.

| 이벤트 | 목적 |
|---|---|
| `search` | 검색어 기반 콘텐츠 갭 발견 (원문 저장 여부는 개인정보 최소화 관점에서 검토) |
| `panel_toggle` | 자료 패널 사용률 검증 → 기능 유지/개편 판단 |
| `toc_graph_interact` | 그래프 목차가 실제로 쓰이는지 검증 |
| `resume_download` / `contact_click` | 포트폴리오 전환 측정 |

**운영 규칙**
- 도입 시 `/privacy/`에 짧은 개인정보 처리방침을 두고 **`privacy`를 R15 예약어에 추가**
- 도입 시점: **M7**(마감) 확정. 다만 런치 시점부터 지표를 보고 싶으면 M5로 앞당겨도 비용은 동일하다(스니펫 1줄)
- **비가역 결정이 아니다.** 지금 미도입을 골라도 나중에 스니펫 한 줄로 추가되며, 반대로 도입 후 제거도 간단하다

# 본문 섹션 ↔ 보조자료 연결 설계 (제안 v1)

- 작성일: 2026-09-26
- 상태: **제안** — 10장의 질문에 대한 결정 필요
- 관련: `docs/PLAN.md` 9장 · `docs/design/panel-spec.md` · `docs/authoring.md`
- 이 문서는 **메인 기능**으로 취급한다.

---

## 1. 배경 — 이전 구현을 롤백함

M3 후속으로 넣었던 "자료 ↔ 본문 참조 평행 정렬"(절대 배치 + 페이지 스크롤 연동)을 **되돌렸다.**

| 문제 | 내용 |
|---|---|
| 시각적으로 잘 드러나지 않음 | 정렬이 되어도 사용자가 그 사실을 인지할 단서가 없음 |
| **자료가 화면 밖으로 사라짐** | 2번 자료를 보려는 시점에 카드가 패널 위쪽(화면 밖)에 있어 볼 수 없음 |
| 구조적 원인 | 패널 높이와 본문 높이의 비율이 달라 "선형 연동"만으로는 항상 화면 안에 둘 수 없음 |

**롤백 범위**: 정렬 JS·CSS·`materials-list` 래퍼·관련 이벤트 제거. **인쇄 버튼은 유지**(별개 기능).

---

## 2. 목표 (사용자 설계 의도)

1. 본문을 내려가면 **그 구간에 필요한 보조자료가 패널에 따라 뜬다**
2. 비유: **왼쪽은 웹소설, 오른쪽은 웹툰** — 왼쪽 글에 맞춰 오른쪽 그림이 바뀐다
3. 본문을 **섹션**으로 나누고, 각 섹션이 보조자료 하나와 연결된다
4. 섹션을 시각적으로 나눌지(1안) 여부는 별도 결정

## 3. 마커 문법 — `{...}`는 사용할 수 없다 (실증)

요청하신 `{fig-venn}` 표기법을 그대로 넣고 빌드한 결과:

```
[ERROR] ReferenceError: fig is not defined
[ERROR] [build] Caught error rendering /blog/sample/zz-marker-test/
```

**이유**: `.mdx`에서 `{ ... }`는 **JSX 식(expression)** 이다. `{fig-venn}`은 `fig - venn` 이라는 뺄셈으로 해석되어 `fig`가 정의되지 않았다는 오류가 난다.
`{}`(빈 중괄호)도 식으로 해석되어 객체로 취급된다.

> 요청하신 "다른 md문법과 충돌하지 않는 문법을 구상"의 결론: **중괄호 계열은 전부 불가**하다.

### 3.1 후보 비교

| 후보 | MDX 안전 | 파싱 난이도 | 저작 편의 | 비고 |
|---|---|---|---|---|
| `{id}` | ❌ **빌드 실패** | — | — | 사용 불가 |
| **`<Section id="fig-venn" />`** | ✅ | **플러그인 불필요** (MDX AST에 남음) | 보통 | 컴포넌트가 DOM 앵커를 만들 수 있음 |
| `::section[fig-venn]` | ✅ | `remark-directive` + 변환 플러그인 | 좋음 | 마크다운스러움. 의존성 1개 추가 |
| `<!-- fig-venn -->` | ✅ | remark/rehype 플러그인으로 span 변환 | 좋음(짧음) | 화면에 안 보여 오타 발견이 어려움 |
| `@@fig-venn` | ✅ | 커스텀 플러그인 | 좋음 | 본문 텍스트와 충돌 가능성이 0은 아님 |

**권장: `<Section id="fig-venn" />`**

- 우리는 이미 **Unified 프로세서**를 쓰므로 플러그인 추가가 가능하지만, 이 후보는 **플러그인이 아예 필요 없다**(MDX가 파싱한 결과를 그대로 읽으면 됨)
- 마커가 **DOM 앵커**로 렌더되므로 런타임 위치 측정이 자연스럽다
- 빈 섹션은 `<Section />`
- `<FigureRef>`와 같은 컴포넌트 계열이라 저작 규칙이 일관된다
- 검증 스크립트가 정규식/파서로 id를 바로 뽑을 수 있다

**2순위: `::section[fig-venn]`** — 마크다운 느낌을 원하면. 단 플러그인 1개 추가가 필요하다.

## 4. 섹션 모델

### 4.1 규칙

```
<Section id="fig-venn" />      ← 섹션 1 시작. 자료 1(fig-venn)과 연결
본문 1
<Section id="note-symbols" />  ← 섹션 2 시작. 자료 2와 연결. 섹션 1은 여기서 끝
본문 2
<Section id="fig-venn" />      ← 섹션 3. 같은 자료를 다시 호출(중복 허용)
본문 3
<Section />                    ← 섹션 4. 빈 섹션(자료 없음). 경계 역할은 함
본문 4
<Section id="does-not-exist" /> ← 섹션 5. 없는 id → 빈 섹션으로 예외 처리
본문 5
```

| 규칙 | 내용 |
|---|---|
| 마커 의미 | 섹션의 **시작**. 다음 마커 직전까지가 그 섹션 |
| 중복 호출 | 허용. 같은 자료를 여러 섹션에서 연결 |
| 빈 마커 (`<Section />`) | 자료 없는 빈 섹션. 경계 역할은 유지 |
| 없는 id | 빈 섹션으로 처리(경고만). **빌드를 실패시키지 않는다** |
| 마커가 없는 글 | 섹션 개념 미적용 → **기존 동작(전체 자료 목록)으로 폴백** |
| 문서 첫 마커 이전 | "머리말" 구간. 연결할 자료 없음 |

### 4.2 인쇄 규칙 (충돌 방지)

- **인쇄 부록은 `materials:` 에 적힌 자료를 순서대로 1회씩만** 출력한다
- 본문에서 여러 번 호출해도 인쇄에는 영향이 없다
- 섹션 구분선/번호 뱃지는 인쇄에서 생략하거나 최소화한다

### 4.3 새 검증 규칙

| ID | 규칙 | 수준 |
|---|---|---|
| R16 | `<Section id="...">` 의 id 가 `materials` 에 없음 → 빈 섹션 처리 | 경고 |
| R17 | `materials` 중 **어느 섹션에서도 호출되지 않은 자료** | 정보(경고) |
| R18 | 같은 글에서 `<FigureRef>` 와 `<Section>` 의 id 불일치 없음 (`FigureRef`는 그대로 검증) | 오류 |

## 5. 패널 동작 메커니즘 — 3가지 대안

| | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A** | **연속 평행 스크롤** (이전 구현) | 이론적으로 가장 "평행" | 높이 비율 차이로 **화면 밖으로 사라짐**(실측), 구현 취약 |
| **B** | **활성 섹션 추적형** — 현재 읽는 섹션의 자료를 패널 상단 고정 위치에 표시하고, 섹션이 바뀌면 교체 | **항상 화면 안**에 있음. 높이 비율 무관. 중복/빈 섹션 처리 자연스러움. 웹툰 비유와 부합 | "동시에 두 자료"를 볼 수는 없음 |
| **C** | 하이브리드 — 활성 자료를 크게 + 아래에 "다음 자료" 미리보기 | 정보량 최대 | 화면이 복잡, 구현 복잡 |

**권장: B (활성 섹션 추적형)**

- 보고하신 버그(자료가 위로 사라짐)가 **구조적으로 발생하지 않는다** — 표시 위치가 항상 패널 상단 고정이기 때문
- 본문 높이·패널 높이 비율에 의존하지 않는다
- 섹션 = 자료 1개 매핑이므로 "지금 읽는 구간의 그림"이라는 웹툰 비유에 정확히 맞는다

### 5.1 B의 상세 동작

1. **활성 섹션 판정**: 읽는 기준선(예: 뷰포트 상단 + 25%)보다 위에 있는 **마지막 마커**의 섹션이 활성
2. **패널 표시**: 활성 섹션의 자료를 패널 본문에 표시. 섹션이 바뀌면 **200ms 페이드/슬라이드**로 교체
3. **빈 섹션**: 표시할 자료가 없음 → 이전 자료를 유지하고 `이 구간에 연결된 자료 없음` 배지를 잠깐 표시 *(10장 Q4에서 선택)*
4. **목록 보기 전환**: 패널 상단에 `따라오기 / 전체 목록` 토글을 두고, `전체 목록`은 지금처럼 `materials` 전체를 스크롤로 보여준다 *(10장 Q5)*
5. **양방향 강조**: 패널의 자료 카드에 마우스를 올리면 본문의 해당 섹션이, 본문의 섹션에 마우스를 올리면 패널 카드가 강조된다
6. **기본값**: 마커가 있는 글 → `따라오기`. 마커가 없는 글 → `전체 목록`

### 5.2 오버레이(<1024px)

- 기존과 동일하게 시트/드로어로 표시하며 **따라오기 동작은 하지 않는다**(화면 밖이라 의미 없음)
- 다만 시트를 열면 **현재 섹션의 자료가 맨 위에** 오도록 스크롤 위치만 맞춘다(선택)

## 6. 본문 시각 처리 — 1안 / 1안-라이트 / 2안

| | 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|---|
| **1안** | 섹션 블록화 | 각 섹션을 카드/테두리로 **감싼다**(DOM 래핑). remark 플러그인으로 mdast를 분할해야 함 | 구조가 한눈에 보임 | 읽기 흐름이 바뀜, 인쇄·앵커·접근성 영향, 구현량 큼 |
| **1안-라이트** | 구분선 + 번호 | 마커 위치에 **얇은 구분선 + `① 자료 제목` 뱃지**만 표시. DOM 래핑 없음 | 시각적 단서 제공, 읽기 흐름 유지, 구현 단순 | "블록" 느낌은 약함 |
| **2안** | 변화 없음 | 본문 렌더링 그대로. 패널 연결만 | 가장 안전 | 섹션 구조가 보이지 않아 기능 존재를 인지하기 어려움 |

**권장: 1안-라이트 + 양방향 강조(5.1-5)**

- `<Section>` 컴포넌트가 스스로 **구분선 + 섹션 번호 + 연결된 자료 제목**을 렌더하면 되므로 **플러그인이 필요 없다**
- 호버/활성 시 배경을 옅게 칠해 "이 구간 ↔ 저 카드"가 즉시 보이게 한다
- 인쇄에서는 번호 뱃지 정도만 남기고 장식은 제거

> 1안(블록화)을 원하시면 remark 플러그인으로 mdast를 분할하는 별도 작업이 필요하고, 표·수식·`<Callout>`·인쇄에 미치는 영향을 점검해야 한다. **먼저 1안-라이트로 써 보고 블록화를 결정**하는 것을 권한다.

## 8. 계약(스튜디오) 관점

- 프론트매터 구조는 **변하지 않는다**(`materials` 그대로)
- 본문에 `<Section id>` 가 추가되므로, 검증 계약 JSON에 **섹션 정보**를 추가한다:
  ```jsonc
  "posts": [{ "id": "...", "sections": [{ "index": 1, "materialId": "fig-venn" }, ...] }]
  ```
- `contractVersion` 을 **2로 올린다**(필드 추가이지만 스튜디오가 활용해야 하는 정보다)
